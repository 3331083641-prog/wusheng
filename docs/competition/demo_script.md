# 约 5 分钟演示脚本

## 开场（30 秒）
启动 scripts/start.ps1，打开 http://127.0.0.1:5173。首页显示统一导航、活的 Demo 面板与数据库物品总数。说明：免费本地原型，初始10件合成物品，不是商业 SaaS。

## Case A：添加耳机（90 秒）
1. 添加物品 → 上传 frontend/public/assets/headphones-detail.jpg 与 docs/references/demo-receipt.png。
2. 第二张类型选择小票/发票，点击开始识别。
3. 观察本地扫描与逐字段置信度；Sony、WH-1000XM6、2999、购买日期等来自 OCR。纯照片缺少文字时系统明确说明未找到，而不假装模型识别。
4. 名称可改为“我的 Sony 耳机”，确认真实购买日期。演示票据日期固定为2026-10-01，未来演示请改为当天，或使用自己票据。
5. 确认并保存 → 档案 → 生命周期；提醒中心出现退换与保修。各页总数共同变化。
6. 打开“凭证资料”，展示来源图片、原文、置信度与人工修改标记，补充或分类凭证；下载售后 ZIP 与 JSON。二维码演示需另启 scripts/start_lan.ps1，在电脑本机管理入口生成只读二维码；默认本机模式会明确提示手机不可访问。

## Case B：空气净化器滤芯（60 秒）
1. 耗材管理 → 空气净化器滤芯 → 右侧趋势抽屉。
2. 解释合成场景为60天观察区间、5单位历史使用、1单位当前库存，日均5/60，剩余1÷(5/60)=12天。
3. 这是算法 Demo 场景，不表示厂家滤芯正常寿命。现实可按实际消耗或等效用量记录。
4. 记录实际补货或消耗，观察库存、预测、数据质量与经验区间；在历史中撤销错误记录。不同耗材的单位不直接作生活开销比较。

## Case C：洗衣机维修（90 秒）
1. 新增维修记录，物品选洗衣机，问题“脱水异响”，报修当天。
2. Drawer 按顺序保存待预约→诊断中→维修中→完成，费用450元，备注实际维修内容。
3. 物品详情出现报修、完成与继续使用节点；数据统计维修支出增加450元。
4. 原 Demo 洗衣机还保留一条诊断中记录，若只完成新记录，仍显示维修中，这是多个未完成维修的真实一致性行为。可把原记录也完成，或用新建洗衣机演示独立闭环。

## 助手与总结（50 秒）
耳机上下文问“还在保修吗”“多久清洁”；回答引用档案与 Demo PDF。切换行李箱问维修，明确无记录。可展示用户触发的扫描 PDF OCR、环境变量配置的现有本机模型模式、ICS 日历与统计页完整备份。
强调真实原创点与开源边界；默认规则模式无需 API Key。纯照片视觉识别、向量 RAG、关闭应用后的后台通知尚未实现；系统日历负责应用关闭后的提醒。局域网、真实手机相机及 PWA 安装按 README 的人工步骤另行演示，不伪造实机验证。
