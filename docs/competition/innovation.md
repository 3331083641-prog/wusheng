# 物生创新与已有能力边界

## 开源参考
Warden：本地小票 OCR、保修/退换双期限、测试到期提醒、可测试的纯日期逻辑。
HomeInventory：家庭物品结构、维护、QR、附件、低库存思想。
上述不是物生原创。未直接复制源码。

## 我们自主设计
1. Item Lifecycle Engine：物品状态、保修/退换时间与重复维护维修事件联合建模；幂等协调提醒。
2. 多模态物品自动建档：接收物品、票据、包装与说明书图片，本地 OCR 提取文字候选，保留 sourceImage、confidence、原文并融合冲突。当前主要为 OCR 多来源融合；无文字物品视觉分类未启用。
3. Lifecycle Event Graph：时间节点与原始记录证据边，API /items/{id}/event-graph；维护与维修回流。当前为事件有向关系结构，不是图神经网络。
4. Device–Consumable 关联模型：设备、耗材、消耗与补货分别存储。
5. 消耗速度预测：根据观察窗口内真实记录计算日均消耗、剩余天数和提前采购日期；对无历史拒绝给数字。附记录数、观察跨度、low/medium/high 数据质量与波动估算区间，明确区间不是统计置信区间。
6. AI 生命周期建议：默认档案规则，另由 ProviderFactory 接通用户配置的本机 Ollama / OpenAI-compatible 服务，检索当前物品的有限相关段落并返回来源；未安装或请求失败自动回退。已验证模拟服务协议与隔离，并用本机已有 Qwen3-VL-4B-Instruct 完成两个真实档案问答；未下载大模型，也不将冒烟验证当作质量基准。
7. 物品专属知识上下文：ContextBuilder 限定当前 itemId，避免跨物品混答。
8. 说明书知识库：PDF 本地存档、文本层提取；扫描件由用户显式触发 PDFium 渲染与 RapidOCR，保存状态、页数及文本来源，失败保留原文件；轻量关键词/中文二元组检索，非向量 RAG。
9. 一物一码生命周期入口：动态检测私人局域网地址，单端口生产 SPA；安全随机令牌的手机只读档案与 PNG 下载，支持重生成及撤销，管理 API 限本机。二维码库是开源现成能力，创新在于访问边界与生命周期入口的结合。
10. 生命周期驱动的数据统计：维护、维修、提醒与补货记录统一统计，不写死指标。
11. Field-level Evidence Provenance：候选、当前值、来源图片、原始 OCR 文本、置信度及人工修改状态分别呈现，不将人工改正计为 OCR 成功。凭证中心支持建档后追加、分类与删除真实本地图片。
12. 售后证据包：当前物品资料、原图、可选 PDF、中文摘要 PDF 和 SHA256 清单组成 ZIP，可离线核验；不替代厂商售后审核。
13. 可纠正的本地数据闭环：维护编辑/删除、消耗/补货撤销、维修元数据纠正；撤销拒绝负库存，维护和统计同步更新。
14. Local First 完整备份：SQLite 一致快照、引用附件、哈希及版本清单，恢复前验证与备份、失败回滚；仅单进程运行，恢复不自动销毁旧附件。
15. 主动提醒边界：用户显式授权的运行中浏览器通知与单条/批量 ICS 日历导出；不宣称关闭应用后仍提供后台通知。

## 可验证价值与限制
Case A 票据中名称、品牌、型号、日期、金额、序列号和保修可自动提取，用户逐项确认。能减少部分字段输入，尚未进行真实家庭用户的大样本耗时对照评测，不报告虚构节省比例。
Case B 合成的 60 天 / 5 单位消耗历史 + 1 单位库存 = 12 天可用，算法确定可复算。
Case C 维修流转、费用、事件与统计共用真实数据库并通过测试。

可部署且无需在线 API。比赛能力界限应表述为开源 OCR + 可追溯规则融合 + 统计预测 + 证据检索问答 + 可选本机模型接口，不称为全自主大模型。渲染、OCR 推理、二维码编码、ZIP/PDF 基础能力属于第三方或标准库；业务关系、上下文边界、记录协调及工作流由项目实现。

OCR Benchmark 通过脚本从合成标签实际运行 RapidOCR，3 张图共 15 个真值字段，14 个完全匹配，precision/recall/F1 均为 0.9333；样本规模很小，不代表真实家庭票据准确率。原始候选、真值与可复现方法见 [OCR 基准](ocr_benchmark.md)。PWA manifest、静态资源服务工作线程及手机拍照入口已实现；真实手机相机和 HTTPS 安装需人工复核，未声称已完成物理设备测试。
